# 阶段0 冻结的 3 个反例场景(手写描述)

这 3 个场景是本课题主张(§6.14/§13.9)的核心可证伪点:
"机器人不能因为一个 IK 解就瞬间出现在箱子另一侧"。
阶段0 只冻结描述与配置;真正的自动化判定 test_edge_no_teleport.py
属于阶段4(第9–12周),届时才实现 base C-space + flood-fill 连通性。

## EC1 开阔区:应接受(§10.8.1-1)
箱子在开阔地,机器人从后表面模板走到左侧面模板,
二维地图上存在无碰 base 路径。
期望:reposition 边合法,方法接受。

## EC2 箱子横在门中:应拒绝(§10.8.1-3,主反例)
门前目标站位与门后目标站位的双手 IK 都可解,
但箱子横堵门洞,使 base 自由空间 F_B(qo) 的两个连通分量断开。
期望:κ(门前站位) ≠ κ(门后站位),reposition 边直接拒绝,
      R_teleport 必须为 0。这正是 §11.8 图2 的反例图。

## EC3 箱子移开后连通性恢复:应接受(§10.8.1-5)
同 EC2 的门,但箱子先被推离门口。
期望:此时 F_B(qo) 重新连通,κ 相同,reposition 边恢复合法。
      说明连通性必须随箱子位姿重新计算(式6.4),不能静态缓存。
